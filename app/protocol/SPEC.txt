Dive Watch protocol 1 — implemented application contract
=======================================================
This is a project-specific protocol over Nordic UART Service, not a Nordic dive-log standard.
NUS service 6e400001-b5a3-f393-e0a9-e50e24dcca9e
RX/write-with-response 6e400002-b5a3-f393-e0a9-e50e24dcca9e
TX/notify 6e400003-b5a3-f393-e0a9-e50e24dcca9e

All integers are little-endian unless specified. UUIDs are 16 bytes in network/RFC 4122 byte order.
Strings are UTF-8, prefixed by an unsigned 8-bit byte length. No C struct padding.
A connection starts with discovery and TX notification subscription, then HELLO.
No security/authentication guarantee is provided by the initial simulator.

Frame header (8 bytes):
 u16 total_length, including header, range 8..4096
 u8 major_version = 1
 u8 opcode
 u16 request_id, range 1..65535
 u16 flags: bit 0=response, bit 1=error; other bits zero
 followed by total_length-8 payload bytes.
One request is outstanding at a time. Responses repeat opcode and request_id.
Trames may span several BLE operations; fragments are not separate messages.
Each BLE fragment must fit negotiated ATT MTU-3 and local limits. On disconnect,
discard a partial frame and keep durable validated blocks.

Commands:
 01 HELLO: request empty. Response UUID watch_id, u8 origin (0=real,1=simulated),
    string model, string firmware.
 02 GET_STATUS: request empty. Response u8 state (0=surface,1=diving,2=unknown),
    u8 battery (0..100,255=unknown), u16 completed_dive_count.
 03 LIST_DIVES: request u32 cursor (first=0). Response u32 catalogue_revision,
    u32 next_cursor (0xffffffff=end), u16 count (max 50), then count manifests.
    Only completed dives. The same revision must cover all pages; otherwise restart.
 04 GET_MANIFEST: request UUID dive_id. Response one manifest.
 05 GET_BLOCK: request 32-byte SHA-256, u32 offset, aligned to block_size and <file_size.
    Response u32 offset, u16 data_length, u32 CRC-32, then data bytes.
    data_length = min(block_size, file_size-offset).
 06 ERASE_COMPLETED: request UUID watch_id, 32-byte catalogue fingerprint.
    Fingerprint = SHA-256(u16 total_count + concatenated manifests in LIST_DIVES
    order across all pages). Reject another watch, active/unknown dive state,
    or changed catalogue before modifying storage. Erase completed files atomically,
    increment catalogue_revision, then reply u16 deleted_count. Never erase settings,
    firmware, identity or a running dive. The phone offers this only after every
    manifest identity/hash is present in its local logbook and explicit confirmation.
    A missing reply leaves the outcome uncertain: reconnect and read catalogue;
    do not automatically resend an old erase request.
 07 GET_CAPABILITIES: request empty; response u32 bits, bit 0=ERASE_COMPLETED.
    Unknown command (code 1) from older devices means erase is unsupported.
 Error response: flags=3; u16 code (1=unknown command,2=invalid request/not found,
    3=active dive,4=catalogue changed).
 Unknown command payloads are never interpreted as profile data.

Manifest (67 bytes):
 UUID dive_id; u8 mode (0=apnea,1=air scuba); i64 start_utc_ms (-1=unknown);
 u32 duration_ms; u32 file_size (1..16777216); 32-byte SHA-256; u16 block_size (1..1024).
 An immutable completed file is identified by (watch_id,dive_id) and SHA-256.
 Same identity/hash = no-op. Same identity/different hash = conflict, keep original.

File header (62 bytes):
 ASCII DWLG (4); u8 version=1; u8 mode; u16 flags (bit 0=simulated);
 UUID watch_id; UUID dive_id; i64 start_utc_ms (-1=unknown);
 u32 duration_ms; u32 nominal_sample_interval_ms; u32 sample_count (1..1000000);
 u16 event_count.
Samples immediately follow, 8 bytes each:
 u32 elapsed_ms; u16 depth_cm (65535=unavailable);
 i16 temperature_centi_c (-32768=unavailable).
Then events, 15 bytes each:
 u32 event_id; u32 elapsed_ms; u16 event_code; u8 severity;
 i32 raw_value (-2147483648=unavailable).
No trailing bytes. Sample times strictly increase and stay within duration.
Event IDs are unique within the dive; unknown event codes are preserved.
Code 1 is a fictional depth alert in simulator fixtures; firmware event semantics
are not yet standardized. The phone does not calculate dive alerts/decompression.
A gap larger than 1.5 nominal intervals breaks the drawn profile; no interpolation
across missing data. A full-profile mean is unavailable when coverage is incomplete.

CRC-32/ISO-HDLC: reflected, init 0xffffffff, polynomial 0x04c11db7,
xorout 0xffffffff; CRC over block data only, transmitted as little-endian u32.
Test: CRC32(ASCII "123456789") = cbf43926.
SHA-256 covers the complete canonical file, header and event list included.
Neither checksum authenticates a peripheral.

Flow: manifest -> block request -> CRC check -> fsync and atomic block publication
-> persist progress -> next block request. Complete-file SHA and structural checks
precede the Room transaction publishing the dive. No extra ACK per notification.
On timeout, disconnect; reconnect and repeat HELLO/catalogue/manifest before retry.
The first implementation retains blocks and asks for manual retry after a failed
request; it does not silently run unlimited retries. Cancellation stops new requests.

Fixtures in fixtures/ are generated by the independent Python implementation.
Kotlin tests decode them, re-encode byte-for-byte and compare manifest and SHA-256.
The literal HELLO request vector is 0800010101000000.
The simulated watch identity is stable; all fixtures retain origin=simulated.
The simulator's deletion lasts for the current process. Restarting it generates
the three fictional fixtures again. Future firmware must persist deletion.

Future firmware updates use a separate MCUmgr/SMP service and are not implemented.
